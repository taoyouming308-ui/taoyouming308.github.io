# 现金全额收银：提交与原请求核对

状态：独立分支、本机合成数据库验证；不是正式上线。旧 13 模块原型、原三个 App、真实 Auth/Edge 均未接入。

## 本批闭环

载入待收银订单 → 重新读取版本与应收 → 现金/找零预览 → 人工确认 → 原子收款及商品出库 → 原请求支付记录核对 → 读取订单现状 → 清除待核对清单。

金额预览不写业务。只有确认后生成冻结请求；页面输入、订单版本或范围变动使预览失效。只支持现金全额正金额，不支持零元、混合支付、电子支付或会员扣款。

## 数据库及接口

- CLI 生成迁移 20260908045658_salon_cash_checkout_versioned.sql。新 cash_checkout → salon_checkout_cash，与旧 checkout 分开；既有接口及其调用方不迁移，旧无版本入口仍需上线前收敛。
- 当前 staff/store 由服务端验证；需要 orders.checkout 和 orders.read。仅 service_role 执行，SECURITY INVOKER、空 search_path；浏览器没有业务表权限。
- 全部 RPC 输入进入员工请求指纹；同键不同参数/员工拒绝，同键已成功先回历史结果，不重复扣库存。仍重新校验现权限。
- 锁定订单后比较 expectedVersion、待收银状态、非空明细和全额应收。金额文本严格最多两位小数，不接受指数或四舍五入输入，实收不能少于应收。
- 商品按 ID 顺序锁库存；要求当前店已启用库存及足够余量。出库、支付、订单状态、审计和请求完成在同一事务，任一失败全部回滚。没有会员流水写入。
- 不接受订单已有 pending/confirmed 支付的重复现金结算。不同请求并发同单，最多一笔成功。
- 返回组织/门店/订单/支付 ID、原请求号、原版本、现金支付金额/实收/找零。支付与找零分别记录，找零不计收入。

## 结果未知与历史状态

同页丢包只允许原键原参数重试。首次明确拒绝可清单；已有未知提交后再被拒绝，保留待核对清单。成功回执字段不匹配不视为确认。

request_lookup 的 cash_checkout 分支按组织、店、员工、原请求号和动作读取已完成请求，并连接具体支付记录，验证订单、现金方法及三项金额；不只看订单 paid。查询使用 READ ONLY 可执行，当前收银/读取权限仍必需。

提交成功还须核对原请求支付记录及订单现状，之后才能清单。回读失败关闭写重试，保留请求编号，改为只读核对。刷新后重新验证身份，再查询；不再提交业务。sessionStorage 仅保存 operation/requestKey，不存金额、顾客资料、令牌或支付载荷。

历史收款和当前状态分开展示；之后全额退款、部分退款或其他状态变化不代表原请求未收款，不允许因此补收。当前页面不展示退款分配明细，不是净收款报表。退款执行链另行验收；本批只用合成历史状态夹具验证恢复。

关闭标签页/清除存储、跨设备恢复、人工处理无回执请求仍待开发；不能承诺所有未知状态均可自动恢复。
