# 现金收银页面第一批：金额预览

历史阶段记录：2026-09-08 第二批已新增独立现金提交与原请求核对，现状见 [现金收银闭环](salon-cash-checkout.md)。以下描述仅为第一批预览边界；预览操作本身仍不写业务。

状态：本机合成数据、独立开发分支。仅预览，不是收款完成；没有开放 checkout。

## 已实现

从本店列表“载入订单处理”，仅当前待收银、有明细、应收大于零的订单可输入拟收现金。点击“核对订单并预览找零”会重新读取订单，核对组织、店、编号、状态、编辑版本、应收与明细数量；与载入时不同则拒绝预览，要求重新选单。

应收使用服务端总额，不从项目重算、不改优惠。拟收现金必须为十进制非负金额，最多两位小数，上限与既有 numeric(12,2) 一致；少于应收不能预览。应收、现金、找零使用整数分计算，输出固定两位小数，不把找零计入收入。

结果明确标注“未确认收款”，不是回执，也不是库存/收银权限已通过的凭证。仅现金全额，不支持混合支付、会员、电子支付、零元结算、退款。

修改输入、重新载入、写业务、刷新本店、读取失败或订单变化清除旧预览；切店、退出、身份失效和离开编辑同时清除输入与预览。输入仅内存，不保存 localStorage/sessionStorage；重选相同订单也要求重填。普通只读查看仍不改变当前处理对象，预览明确显示所处理单号。

## 接口边界

新增纯模块 cash-preview.mjs 和本机静态模块白名单。沿用已授权 order_detail，没有新增业务 API、数据库迁移、表权限、写请求或支付 payload。统一客户端与本机服务仍未开放 checkout；没有伪装禁用但可提交的收款按钮。

按 Supabase 技能核对现有函数及[官方权限说明](https://supabase.com/docs/guides/database/functions)，保持浏览器不直写表、身份和门店由已有服务端验证。收银提交会联动支付、会员和库存，因此本批不将已存在的后台收银函数直接绑定页面。

- 仅合成环境。不代表正式 Auth、Edge、Advisor、真实收款或上线验收。

## 下一批收银提交前必须接通

1. 原子校验读取版本的收银入口、完整金额参数与稳定请求号；不能提交前自动更新版本掩盖变化。
2. 收银专属权限、支付回执投影与完整金额核对；不能只因订单显示 paid 就确认本次请求收款成功。
3. checkout 原请求只读核对及刷新恢复；丢包、成功后回读失败、后续退款状态都不能导致重复扣款。
4. 临时商品库存和收银角色合成夹具、库存不足/撤权/重复凭证/并发收银事务回滚测试。现有基础夹具商品为 stock_tracked=false，不能据预览通过认定商品可以收银。
5. 再接现金提交，之后逐项接电子凭证、会员与组合支付；不更改原资金口径，不自动上线。
