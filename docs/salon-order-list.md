# 本店订单列表与选单编辑

状态：独立分支、本机合成数据验证。未上线、未部署迁移/Edge、未接三个旧 App。

## 使用流程

1. 连接本机测试环境，选择授权门店。
2. 在“本店订单”选择状态，查询最新一页；“下一页”查询更早内部编号，每页最多 50 单。
3. “查看”仅展示原单，不改变当前编辑对象。“载入草稿编辑”重新查询当前记录与版本，只有 draft 且全部明细 pending 才可载入。
4. 未保存修改需确认丢弃；载入失败保留原编辑对象。成功载入本身不写业务，完整保存仍使用原版本、原请求号重试、整单回读校验。
5. “离开当前编辑”只清空内存，不取消或删除数据库订单；之后可新建或从列表继续载入。

筛选变化、列表查询失败、刷新本店、业务写入和退出清除旧列表；请求未知或身份失效时沿用整页锁定。列表不是快照/实时订阅，翻页期间状态可能变化；新增单需重新查询最新页。不提供总单数、跨店合并、日期/顾客搜索、导出或批量操作。

## 接口与数据边界

- `orders` → `salon_list_orders`。身份、组织、门店来自服务端验证，忽略客户端伪造身份字段。
- 可选 `status` 为七种订单状态或空串；`beforeId` 为正安全整数或 null；不接受客户端无限扩大分页。
- RPC 返回 organizationId、storeId、rows、nextBeforeId。每行仅 id/order_no/status/created_at，不返回顾客、员工、备注、金额、会员、支付或完整回执。
- 按 id 倒序游标查询，取 51 行探测下一页，返回前 50 行；组织/门店/编号及组织/门店/状态/编号索引支持两类查询。
- 新函数 STABLE、SECURITY INVOKER、空 search_path；每次检查 orders.read，撤销 PUBLIC/anon/authenticated EXECUTE，仅授予 service_role。没有开放浏览器表访问。编辑按钮不是写权限凭证，实际保存仍由原 RPC 校验 orders.write 和优惠等权限。
- 不新增写入函数或日志正文，不改变财务算法、支付或会员流水。原按内部编号查询仍只读。

## 验证与限制

`test-salon-order-list.cjs`：临时 PostgreSQL READ ONLY 事务分页、跨组织/店/撤权与函数权限；1280/390 Chrome 查询、翻页、文字安全、查看不绑定、选单保存、刷新重选、丢弃确认、旧列表状态变化、编辑版本冲突、读取失败与退出清除。仅使用合成数据。

Supabase 技能检查采用最小函数权限，Postgres 技能采用游标分页；参考 [官方函数权限说明](https://supabase.com/docs/guides/database/functions)。官方更新摘要未发现本批所用函数调用的相关破坏性变化。

本地 `supabase db advisors --local` 因默认本地实例未运行无法完成；没有改连生产。专用临时 PG 测试不等于正式 Auth、真实 Edge/PostgREST 或线上 Advisor 验收。上线前仍须完整测试环境验证与人工确认。
